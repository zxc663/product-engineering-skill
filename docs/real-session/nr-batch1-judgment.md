## 二、产品包自然触发判定：**NR1 失败（价值最高的发现）→ 断点定位 → v0.2.2 修复 → NR6 验证中**

- **失败事实**：NR1 任务「给这个项目做一个番茄钟计时页面…」精确命中 SKILL.md description 触发词（「做一个XX页面/工具/应用」）；N6c 注入模拟同款触发 3/3 通过；但 NR1 真会话**未加载产品包**——无层级门声明、无六问表、无 statechart JSON、无绑定清单（工作区 grep 实证）。其 L7 思维（4 态状态机）出现在设计档散文里，属工作流「设计铁律」产物，不能记为产品包触发。
- **断点定位（NR4 诊断链）**：①技能清单可见 ✅（NR4 明确列出 shisan-xinuo-product 含路径）②注入 ✅ ③hooks ✅ → **断点=模型选择层**：清单可见但模型未选择加载。头号嫌疑=触发词串位于 description 中尾部、头部为机制叙述，选择显著性不足（NR4 引用该条时只复述出头部机制概要——旁证；截断假说未定案，NR5 通道失败已止损）。
- **修复（v0.2.2，双副本同步 4837f5e）**：description 重构——触发短语前置到头部+「新任务即命中，先加载本包再动手」指令+机制叙述后移。该修复在「截断」与「竞争显著性」两种病因下均为正确方向（低后悔）。
- **验收（NR6+NR8+NR12 三样本，03:16-05:54 完案）**：NR6；**触发成功**。NR6 流水自证「能力检索命中并加载 shisan-xinuo-product」；产物=轻量契约（六问/六态矩阵/spec-trace/验收 6 条）+pomodoro-statechart.json；statechart-gate 自跑+主会话独立复跑双 exit=0；实机走查六条验收全过（两轮 1 分钟真实到点、3 截图取证、零报错）；走查揪出真缺陷「输入未提交即开始按旧时长跑」→定性非自动化假象→commit-on-start 修复→修复路径复测；自扩验收+双负载形状；账本写回+提交 988bf66；诚实未验证=铃声听感/系统通知人工感知/深色主题未触发。**A/B 结论（限定 N=1）：v0.2.2 description 前置后，同任务文本从「不触发」变为「全流程触发」——F4 修复验证通过。**
