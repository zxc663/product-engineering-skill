## 〇、我们究竟解决什么问题（问题定义，先于一切机制）

**一句话**：每次会话的模型，都是一个失忆的、只做局部最优的工人，交付完就走；而产品是一个需要有人对全局负责、对承诺持续兑现的有机体。本 Skill 把工匠的三样东西——**地图（项目里已有什么）、厂规（这个项目什么是好的）、验收机（交付是不是真的）**——外置成工人每次上岗必领的工具，让局部优化器每走一步都恰好是全局最优的一步。

**根因=成本结构镜像颠倒**。模型的成本结构（写新代码便宜/复用贵/验证更贵/用户信任=0）与产品的成本结构（写新代码最贵/复用最便宜/验证是唯一真实/用户信任=一切）逐项相反。模型在自己结构里理性的选择，在产品结构里全是毒药。工作流 Skill 已修正「验证」一项（GATE 强制）；本 Skill 修正剩下两项：**让「复用」和「用户视角」从模型的免费品变成必须支付的硬成本。**

**产品=承诺的集合**。按钮是承诺（点了会发生什么）、输入框是承诺（这里该填什么）、错误信息是承诺（你有出路）。四个症状在这个镜头下统一：假理想功能=不兑现的承诺；反人类交互=违背直觉的承诺（JSON 甩脸=把实现细节当对用户的承诺）；组件库闲置=与过去承诺冲突的新承诺（产品精神分裂）；共识不用=对行业承诺的无知。模型的致命点：它只生产承诺的表皮——**兑现发生在交互时，而它只在场于生成时**。本 Skill 的一切工件，本质都是把「兑现义务」从交互时（模型已离场）前移到生成时（模型在场的唯一时刻）。

**反面校验（由此推导的不该做）**：①不写更多抽象原则（原则对失忆工人是噪音）；②不追求「模型拥有审美」（工人永远是新的，给他厂规，审美单源=用户投进账本的票）；③厂规不写一千条（准入测试+上限防废话化）；④每件工件必过检验：「下个会话的失忆工人在哪个动作前、以多少成本、被什么机制强制使用它？」——答不上来的工件，删。

**目的态定稿（2026-09-21 04:33 用户两视频类比）**：市面设计内容绝大多数走「组件技巧/质感提升」路线（7.17 类：六种组件交互提升 App 质感——此类内容太多太多，且是 AI 时代通胀最快的通缩品）——**主题与组件我们一概不定义**。我们定义的唯一对象=**真实用户使用产品时，体验怎么更好**（9.71 类：同一个 APP 有人报价 3 万有人报 30 万——30 万怎么来，清清楚楚）。3 万与 30 万的功能清单可以完全相同，**差价全部在旅程完整性**：第一次打开知道去哪（空态有引导）、等待不焦虑（进度有预期）、出错不慌（错误有出路）、反悔有路（撤销与确认）、下次回来还认识（持久一致）——这正是功能天生六问×六态×双底双顶的全部内容；且每项**可指认、可举证（实机取证）、可验收（联通行三列表）**——30 万的报价单能一行行对应到用户旅程的具体环节，这就是「清清楚楚」。时代论证：AI 把组件与样式的成本压向零（通缩品，人人都有=不值钱），溢价全部集中在体验完整性（稀缺品，需要对真实用户的理解+全程照顾）——**本 Skill 在 AI 时代的存在理由，就是把 3 万到 30 万的差价变成可判定、可生产的清单**。

## 七、效力衰减链（用户九问逼出的缺口命名，2026-09-21 03:42）

一个 Skill 从装上到不起作用，恰好经历五级衰减——九问逐一归因后的链条定稿：
1. **在场不触发**：触发=description×任务语义的概率匹配，非义务；任务不像"设计"则设计系 Skill 整体缺席 → 对策=硬前置条/hook 顶替概率（财务项目 AGENTS.md 已实证）。
2. **计划不引用**：计划从生成习惯长出（写什么码），不从资源清单长出（先查什么表）；只有"查 API"有计划位（对接真相清单），"查品味/查注册表"没有座位 → 对策=计划模板加注册表检索位+归因。
3. **压缩失真**：Skill 入上下文即普通文本，压缩把精确条款降级为摘要残影；重载读进来的还会再被压缩——**上下文内的东西终将失真，这是介质属性不是执行问题** → 对策=条款落盘 references/、判定落盘 scripts/（磁盘不参与压缩）+细则 #326。
4. **仪式化合规**：复述了词汇、走完了流程、产出与不用时一模一样——"读"与"写"之间没有强制函数（复盘自白「合规靠 hooks 非自觉」即此级实锤）→ 对策=生成与交付之间加机器判定，二值化 exit 1 不接受谈判。
5. **产出照旧反人类**：前四级的终点；实机走查 5 缺陷发生时设计系 Skill 全在场=证据。在场≠在决策点；交互的兑现发生在模型离场之后，它永远体验不到自己设计的界面。

**缺口命名**：现有一切机制都作用在模型上下文（劝导生成者），无一作用在交付物上（交付时拦截），拦截结论也不复利。**劝导会衰减，法律不会**——Skill=劝导（高带宽/低强制/易衰减），可复跑工件=法律（零带宽/全强制/抗压缩/exit code 不接受谈判）。本体三层各治一段：判定表治"不知什么是对"，注册表治"不知已有什么"，门禁治"知道也不做"，账本治"做了也白做"。

**偷懒=定价问题，非观念问题**：失忆工人无观念可装（观念需要记忆与利害，两样皆无）；唯一机制=给路定价，让最便宜的路恰好正确——ponytail 提示层（先答要不要存在）/注册表归因层（自研写归因比查表贵，查表成了最省力路径）/门禁执行层（内联样式 exit 1，"快"路变最慢路）。

**态机**（判定表/门禁按项目态切换）：greenfield 拦"发明"（新组件先登记）｜既有项目拦"闲置"（用前必查、自研归因）｜会话内对抗仪式化（输出=代码级引用，不接受"感觉没问题"）｜跨会话对抗压缩（条款/判定/裁决全落盘）｜交付后取证回写（walkthrough 证据进账本=下个会话的厂规）。

**工作流缝合三点**（工作流=调度器，不塞设计条款避免双权威）：①计划时——能力检索/计划模板加注册表检索位（治第 2 级）；②GATE 时——cmd 必含产品门禁可重跑命令、exit 吃真值（治第 4 级）；③收尾时——裁决写回账本为固定动作（治跨会话）。

## 八、工程品味与时序纪律（2026-09-21 03:51 深析定稿；一手源=PG《Taste for Makers》2002 全文+Norman 概念模型/Cooper 目标导向/双钻石共识+财务项目原型即法律实证）

**品味可操作定义**（PG 十四条蒸馏为五能力）：
1. **换位提问**（好设计解决正确的问题）：炉灶四眼四旋钮——"排列最简"是一字排开，正确答案是摆方形，因为问题是「人不假思索就能对应」不是「排列最简」——**问题在错的层面被解决=无品味的原型症状**（PG: The dials are for humans to use / 旋钮是给人用的）。品味第一动作=把问题从机器层面换到人的层面重新提出。
2. **识破装饰**（好设计是简单的）：「装饰常是艺术家说『底下没多少东西在发生』的方式」——直接对应假理想功能（逻辑链上的装饰：看起来在工作）与内联样式（工艺上的装饰：看起来快）。品味=见装饰闻到"底下是空的"。
3. **丑觉先于美觉**：「见丑远比想象美容易；做出美好东西的人多半是在修他们觉得丑的东西」——美是涌现不可枚举，丑是流形可枚举可判定。**品味可执行部分全是否定性知识**=判定表写成零容忍反面清单的理论根据（与 taste-skill 二值化互证，两路独立调研合流）。
4. **敢于复用与敢于重画**：「对」比「原创」重要（复用不是偷懒是自信）；「好设计是重设计」+速写文化（达芬奇一条线打五六遍草稿）=让认错便宜（油彩优于蛋彩：可改的介质放大尝试）。
5. **品味不住在个体里，住在作坊里**：佛罗伦萨 vs 米兰——天才两地都有，作坊只有一处；「把这批工坊拆散，大师或许照样大，学徒群会变小变怯」。**不能给失忆工人装品味，但可以把他派进佛罗伦萨：判定表+账本+门禁=给工人搭的作坊**——本 Skill 的存在理由。

**时序纪律**（用户命题「真实交互逻辑应在设计前预设构想，落地时才考虑代码和源库复用」裁定：**权威序成立，工程化需两处精确化**）：
- 成立依据：Norman 概念模型（先答"用户以为在操作什么"）/Cooper 目标导向设计/双钻石（问题空间先于方案空间）/炉灶旋钮=原始表述。反面病灶=组件驱动设计（先翻库再迁就控件=机器逻辑的人皮）；本项目原型即法律管线（prototypes 先行+P1/P2 管辖落地）为其工程化实证。
- **精确化一：「真实」=态完整**——设计前预设若只是理想路径图，=把假理想功能从代码层前移到设计层（缺陷没少只是更早画出）。真实=六态矩阵逐态过+承诺清单（每元素一句承诺）+失败出路；缺态=设计未完成不得开工（可数→设计档门禁雏形）。
- **精确化二：复用在落地执行、代价认知必须前置**——设计时读注册表**能力索引**（类别级：有什么/缺什么，防幻影构想与强适配），落地时读**组件卡**（API 级+出处归因）；设计档产出必含映射「元素→承诺→兑现方式（现有组件 X/新组件 Y+归因）」。禁止的是把交互决策拖到代码半截让库的顺手悄悄重写承诺——**反人类设计大多不是决策出来的，是一次次"这样改方便"累积出来的**。
- **权威序≠瀑布序**：设计是宪法（管辖落地），落地是执法（复用=兑现方法论），实机走查=司法审查（证据回写账本反哺下版设计——好设计是重设计，账本=制度化的重设计记忆）。一刀切瀑布会把设计变成不可证伪的教条（5 缺陷走查即一轮司法审查）。

**Skill 设计后果三条**：①判定表新增时序纪律条目——组件驱动设计（先选控件后定交互）=一票否决级反面；②注册表双视图：能力索引（设计时读）/组件卡（落地时读）；③设计档准入=六态矩阵可数化（缺态 exit 1）——品味首次前移到代码之前拦截。

**上游 ponytail 深读吸收（2026-09-21，D 档 §6，用户直供链接）**：①第一迭代验收升级为 **agentic 对照实测**（同任务带/不带 Skill、git diff 计分、安全项单列——裸「YAGNI+一行流」口号提示 LOC 降但安全掉到 95%，证明白名单条款才是安全来源，光有极简口号会砍 guard）；②decision-ledger 写回采纳「**ponytail: 注释+定期 harvest**」轻量形态——代码内一行标注「为什么没写/为什么这么定」，收尾命令收割入账，防 later 变 never；③判定表补**阅读义务**条款——阶梯/查表在理解问题之后运行，禁跳过阅读直选档（Lazy about the solution, never about reading）；④caveman×ponytail 正交先例（管说的 Skill×管建的 Skill，零重叠可叠加）=工作流 Skill×产品工程 Skill 双架构的市场验证；⑤hooks 每轮注入（UserPromptSubmit/PreToolUse+模式开关）作为治衰减链第 1/4 级的工程通道备选——ZCode hooks 落地时启用。⑥账本差异化表述修正：ponytail-debt 占了「债务语义」账本位（记为何没写），decision-ledger 的「裁决语义」（记为何这么定）仍空白。

## 九、联通层定稿（Skill 中心对象，2026-09-21 04:09 用户重心校正）

**校正**：Skill 不定义「组件怎么写」——组件库/设计系统域已饱和，做了=重复造轮子；也不以视觉品味为中心——hallmark/taste 红海。**中心对象=产品设计与交互层的联通层**：功能语义 ↔ UI 交互逻辑之间的可判定契约，定义「不难用不难看、更好用更好看」的交互逻辑**怎么来、怎么做**。

**双底双顶（产出标准，四象限+第四底）**——现有调研素材恰好按此整齐归位（定稿正确性的旁证）：
- **不难用（底线，法律）**：功能天生六问全有答案+反面模式零容忍（错误无出路/点了没反应/JSON 甩脸/转圈到底）——ux-feature-design 一票否决+anti-ui-slop inert interactions。
- **不难看（底线，法律）**：AI 味清单零容忍——taste-skill 二值化禁令+vercel 互补条目。
- **无障碍（底线，法律，2026-09-21 学科核实补——F 档缺口 1）**：WCAG POUR 四原则（可感知/可操作/可理解/健壮）不违反——ponytail 白名单与 vercel「语义先于 ARIA」同证；axe 类静态可查（alt/label/对比度/焦点序/键盘可达）。
- **更好用（上限，劝导）**：渐进披露/频率适配/humane automation——ux-feature-design（理论根：认知负荷理论+Hick 定律）。
- **更好看（上限，劝导）**：动画四问/层次质感/craft——emil/impeccable（Norman 行为/反思层）。
底线可数可门禁（exit 1），上限靠判定表+critic 对抗审查推——与 §七「劝导会衰减法律不会」及 §八「丑觉先于美觉（底线是否定性知识可枚举，上限是涌现不可枚举）」同构。

**怎么来——交互逻辑来源三合法**：
1. **用户心智（最强源）**：业界惯例+项目既有裁决。惯例=预装在用户脑里的交互逻辑，用惯例=零学习成本；**反人类设计的高发机制=迫使用户为你的实现学一套新交互**。
2. **功能语义推导**：交互逻辑不是发明的，是功能自带欠条的偿还（功能天生六问，见下）。
3. **红线约束**：出路/六态/承诺不可违（§九产出标准的底线项）。
非法源：组件库存（组件驱动设计）、模型感觉、「看起来酷」。冲突序：红线 > 用户心智 > 功能最优推导。

**功能天生六问（联通层的发动机；2026-09-21 04:56 学科核实后修订=F 档）**：**出处挂靠=Norman 行动七阶段+两个鸿沟的工程压缩版**（七阶段：目标→意图→specific→执行→感知→解释→对照；执行鸿沟=意图vs系统允许，评估鸿沟=系统状态vs用户理解）——非发明，压缩损失已核查（情绪轴/认知负荷，见缺口）。每个功能句天生携带六问——①输入什么（执行鸿沟：示能/意符）②何时发生/要多久（反馈；**量化挂 Nielsen 三阈值：0.1s 即时/1s 心流上限/10s 注意力上限，超 1s 必给进度、超 10s 必可取消**）③成功长什么样、落在哪（评估鸿沟：对照）④失败怎么**防**、没防住怎么**恢复**、恢复给出路（Nielsen #5 预防>#9 恢复，三层缺一不可）⑤能否反悔、代价多大（用户控制与自由，Nielsen #3）⑥下次/换环境还认吗（持久/一致/并发/设备/语言/弱网）。逐问落交互原语=**翻译表**（劝导级第 7 列：情绪目标——该环节用户该感到什么，Journey Map emotion lane）。任问无答案=交互债；答案需用户猜=反人类。六问（提问轴）×六态（渲染轴）的问答对=联通行。

**怎么做——联通工序（工件链）**：功能句 → 六问翻译表 → 承诺清单+六态（态+转换）矩阵——**态间转换必须可感知**（每条箭头标注过渡语义/时长/可中断性；变化盲视=无标记突变是缺陷，G 档 §3）→ **spec-trace 双向门禁**（正向：每条功能行有元素兑现；反向：每个界面元素可回指功能行——反向断裂=发明视觉/自加功能）→ 实机走查取证 → 回写账本。**真联通=双向可追溯+机器可验**；文档联通（写了 design doc）是假联通——写了没按/按了没写都是假联通，只有门禁联通是真联通。

**对 §一/§三 的重心修正**：四问题域中①③④（共识/反人类/假功能）皆属联通层；②「组件注册表」降位为兑现层查询基础设施（落地时读组件卡），不再是 Skill 中心；§三 结构增 `references/interaction-bridge.md`（联通层：来源三合法+功能天生六问+翻译表 schema）。SKILL.md 触发词偏向：「难用/丑/交互逻辑怎么来的/功能怎么变界面/为什么这样交互」。

## 十、强制边界与缺口登记（2026-09-21 04:26 用户两问定稿）

**职责再收窄（用户校正）**：主题/组件**一概不定义**——Skill 不产出任何组件定义、主题、样式，组件内容完全归属上游库；registry 职能=**纯检查者**（查「查没查、归因没归因」），不是定义者。Skill 唯一职责=**规定「这个功能应怎么来」**（联通工序）。「先检查再二次开发、可复用不完全复制」为双重纪律：对模型（先查表再扩展，不照抄上游）+对 Skill 本体（先蒸馏同类再改造，不照抄其文本）。

**真强制清单（用户问一：哪些真正要强制）**——入选判据：可机器判定+在决策/交付点拦截+执行成本低于防止的返工（成本检验）。共九项（2026-09-21 学科核实 8→9，F 档缺口 1）：
1. **六问无空格**：翻译表任问无答案=交互债，exit 1（设计档门禁）。
2. **六态矩阵缺态不得开工**：缺态=设计未完成（可数）。
3. **spec-trace 双向追溯**：正向（功能行有元素兑现）/反向（元素回指功能行）。
4. **查表归因存在**：registry-gate 检查型——自研必须带归因，检查「查没查」而非定义组件。
5. **内联样式/硬编码零容忍**：对齐业界成熟规则（Atlassian plugin/panda no-hardcoded-color），非首创。
6. **dead-binding 逻辑链检查**：死代码/空 catch/未引用绑定（classifyNotice 教训）。
7. **取证存在性**：无真渲染证据（截图/DOM dump）不得声称交互已验证——强制「证据存在」，质量归 critic。
8. **账本写回存在性**：收尾时账本有裁决新增行。
9. **可达性静态底线（F 档缺口 1 补）**：axe 类静态检查不违规（alt/label/对比度/焦点序/键盘可达）——WCAG POUR 的机器可查子集。
其余全部降为**劝导/裁决级**：双上限（更好用/更好看）=判定表+critic；来源三合法优先序=裁决表；阅读义务/反借口表=hook 危险词触发半自动。强制的意义=把衰减链第 4/5 级（仪式化/产出照旧）堵死在交付点；**防仪式爆炸**：强制项逐项过成本检验，新增强制须同门槛准入——宁缺毋滥，强制清单本身就是厂规的一部分。

**能力地图（用户点名缺口）**：衰减链第 2 级（计划不引用）的治具+工作流 Skill×产品工程 Skill 的互补路由层（工作流管怎么做/产品工程管什么是对/地图管什么时候用谁）。行 schema=**动作时点×任务症状→能力（Skill+具体章节/命令）→出口产物**。落位 `references/capability-map.md`；配套 **harvest 机制**（定期扫 skills 目录+frontmatter diff 更新地图——无人维护的地图=第二个失忆）。工作流计划模板增「地图检索位」。**机制先例（E 档 §1.2）**：「项目/」踩坑经验库已在跑同构系统（开工必读+症状关键词检索+四段式+维护时间戳）——不发明新机制，泛化已验证机制。

**新缺口登记（用户问二：还没意识到的新缺口，本轮挖出五项）**：
1. **冲突裁决缺口**：同层 Skill 规则互斥无裁决（工作流 L1 直接做 vs 联通层设计档先行；ponytail 最少码 vs impeccable 打磨）——需优先序表：**底线门禁>流程纪律>品味裁决**；同冲突裁决两次即升格入表（shisan 升格规则同构）。
2. **豁免梯度缺口**：强制清单无作用域声明→L1 小改也被六问淹没→仪式爆炸→模型学会糊弄（仪式化温床）。借 ponytail lite/full/ultra 模式：门禁按改动规模/文件类型分级触发，豁免梯度本身入档可查。
3. **出路活性缺口**：翻译表写满≠写对——错误出路指向死页/死函数，门禁 1-3 全查不出。**新门禁候选 exit-existence gate**：出路目标存在性静态查（路由/函数/页面在吗）——dead-binding 的姊妹件。
4. **触发回归缺口**：触发词命中率只在第一迭代测一次，之后从未回归。触发回归测试集（N 条真实口语任务→命中统计）=ponytail 式 agentic 基准的触发子集。
5. **用户验收面缺口**：全部机制是模型↔工件，用户看不见 Skill 起效。交付报告增「**联通行**」三列表（功能→交互→证据）——spec-trace 的用户可见形态，让「联通」可被用户一眼验收。

**ponytail→工作流 Skill 回补清单（用户点名「ponytail 也有对工作流 Skill 的新补充」）**：①hooks 加模式开关（lite/full/ultra/off）+subagent 注入范围正则——现 hook 为全量注入，无分级；②agent-log 流水借 debt harvest 形态（代码内一行标注+定期收割，防 later 变 never）；③工作流效果用 agentic 对照基准量化（同任务带/不带工作流、真 diff 计分——治「合规靠 hooks 非自觉」的自评不可测）；④命令族化（/review /audit /debt /gain 对应工作流收尾/审计场景）。
